# Add a new ontology term with the reasoner in the loop

A new term rarely breaks an ontology outright. It quietly changes what the
reasoner derives: a property domain makes an unrelated class a subclass of
something, or a disjointness turns the new class into `owl:Nothing`. This skill
makes those effects visible *before* the term goes into the real file.

The checker is `.claude/hooks/ontology-check.sh compare BEFORE AFTER`. It runs
gowl's linter and OWL 2 EL reasoner over both versions and reports:
- **BLOCKING** problems: the file does not parse, the ontology became
  inconsistent, a class became unsatisfiable (with the axioms responsible), or
  a new lint error appeared. It exits 1 when there are any.
- **Placement** of every new class: superclasses that were asserted, and the
  ones the reasoner added.
- **New inferred subsumptions** on existing classes, each with the axioms that
  cause it, and subsumptions that no longer hold.
- **New lint findings**, including `prefer-standard-term` (a standard
  vocabulary already has this term) and `missing-label`.
- New axioms outside OWL 2 EL, which the reasoner skipped.

The same check runs automatically as a PostToolUse hook whenever a `.ofn` file
is edited, so the final edit is verified again.

## Steps

1. **Pin down the term.** From the arguments and the conversation, establish:
   - the target `.ofn` file;
   - the kind (class, object property, data property);
   - the IRI, using the file's existing prefixes and naming style;
   - an `rdfs:label`, and a definition (`skos:definition` or `rdfs:comment`,
     whichever the file already uses);
   - the intended parent(s), and any defining restrictions, such as
     `SubClassOf(:X ObjectSomeValuesFrom(:p :Y))`, domain/range, or
     disjointness.

   Ask only for what you cannot infer. Read the target file first so the
   axioms match its style.

   Do not add terms to `vocab/*/*.ofn`: those files are generated by
   `go generate ./vocab` and hand edits would be overwritten.

2. **Look for a term to reuse first.** Search the standard vocabularies for the
   name and label, e.g. `grep -il "<localname>" vocab/*/*.ofn`. If foaf,
   schema.org, dcterms, skos, prov, org, time or dcat already has it, tell the
   user and suggest reusing it, or aligning with it via
   `EquivalentClasses`/`SubClassOf`, before you mint a new IRI.

3. **Draft on a scratch copy.** Copy the target file twice into the session
   scratchpad, as `before.ofn` and `after.ofn`. Add the declaration, label,
   definition and logical axioms to `after.ofn` only. Prefer OWL 2 EL
   constructs (named classes, `ObjectSomeValuesFrom`, `ObjectIntersectionOf`,
   domains, property chains): the reasoner skips the rest, so its verdict on
   them is incomplete.

4. **Run the check:**

   ```bash
   bash .claude/hooks/ontology-check.sh compare <scratch>/before.ofn <scratch>/after.ofn
   ```

   The first run builds the checker, which takes a few seconds.

5. **Show the user what the reasoner says**, in plain terms:
   - Where the new term lands: "`:Contractor` ends up under `:Human` and
     `:Agent`, though you only asserted ..."
   - Every *new inferred subsumption on an existing class*, with the axioms
     behind it. Ask whether each one is intended; these are the surprises
     worth catching.
   - Any blocking problem, with the responsible axioms and a proposed fix.
   - A `prefer-standard-term` finding, as a reuse suggestion.
   - If axioms were skipped as non-EL, say the result covers only the EL part.

   For more detail on one subsumption, run
   `go run ./cmd/gowl classify -explain "<sub> <super>" <scratch>/after.ofn`.

6. **Iterate** on the scratch copy until the report shows exactly what the user
   intends: no blocking problems and no unwanted inferences.

7. **Apply to the real file** once the user agrees, by editing the target
   `.ofn` with the agreed axioms. The PostToolUse hook re-runs the check
   against the pre-edit version. If it blocks, fix the edit rather than working
   around it.

8. **Report** the term added, where it sits in the inferred hierarchy, and any
   deliberate side effects the user accepted.
